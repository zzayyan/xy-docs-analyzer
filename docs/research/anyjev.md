## Summary

AnyJev is a Python library from Nokia researchers for asking an open-weight LLM a closed question (pick one option, yes/no, or a score) and getting a probability for each option. It reads the model's next-token log-probabilities over the option labels and never parses generated text.
With no training, its `Decider` removes two known biases: preferring an option because of where it is listed, and preferring certain labels in general. Its `Tacit` class runs the authors' own fine-tuned checkpoints in one forward pass, and can hand a capped share of uncertain decisions to the model's reasoning.
It is young and pre-alpha. The repo was created on 2026-09-21, the latest release is v0.3.0, and it is Apache-2.0 with about 1.5k stars. It needs token-level log-probabilities, so it works with transformers, vLLM, SGLang or llama.cpp, but not with Ollama or hosted chat APIs.
For docs-analyzer the relevance is low to moderate. It touches nothing in ingest, Regions or citation rendering. It could make the few yes/no and pick-from-a-list LLM calls (answerability, citation support, section choice) return probabilities. The deployed chat model (Qwen on vLLM) already meets AnyJev's main requirement; Ollama serves only embeddings, which AnyJev never touches.

## 1. What AnyJev is

**Purpose.** You give the model a *state* (text, a JSON-like dict, or a chat transcript) and one or more *typed questions*: `choice`, `noul` (yes/no) or `score`. You get back a `Decision` that holds a probability distribution over the options, read from the next-token distribution, with "nothing parsed" ([README.md#L142-L154](https://github.com/nokia-applied-research/AnyJev/blob/35311c58955716cb8955ce1368a665988bc63735/README.md#L142-L154); [anyjev/__init__.py#L1-L18](https://github.com/nokia-applied-research/AnyJev/blob/35311c58955716cb8955ce1368a665988bc63735/anyjev/__init__.py#L1-L18)). The interface copies "Jev", a product by TypeSafe AI. The repo says it is not affiliated with it ([CREDITS.md#L7](https://github.com/nokia-applied-research/AnyJev/blob/35311c58955716cb8955ce1368a665988bc63735/CREDITS.md#L7); [README.md#L255](https://github.com/nokia-applied-research/AnyJev/blob/35311c58955716cb8955ce1368a665988bc63735/README.md#L255)).

**Problem it solves.** If you read an answer straight from the label logits, it changes when the options are reordered, and it carries the model's built-in preference for some labels ([README.md#L148-L150](https://github.com/nokia-applied-research/AnyJev/blob/35311c58955716cb8955ce1368a665988bc63735/README.md#L148-L150)). On Qwen3-8B with a 20-way BANKING77 task, the README reports these effects of the default `L0` correction: the share of answers that flip when the option order is reversed falls from 0.230 to 0.073, accuracy rises from 0.747 to 0.803, and the share of decisions "auto-decidable at ≤5% error" rises from 7.7% to 46.3% ([README.md#L158-L171](https://github.com/nokia-applied-research/AnyJev/blob/35311c58955716cb8955ce1368a665988bc63735/README.md#L158-L171)). I checked these numbers against the committed result file ([bench/results_v01/2026-09-22/Qwen__Qwen3-8B.json](https://github.com/nokia-applied-research/AnyJev/blob/35311c58955716cb8955ce1368a665988bc63735/bench/results_v01/2026-09-22/Qwen__Qwen3-8B.json)), and a test pins the README table to that file ([tests/test_readme_numbers.py#L11](https://github.com/nokia-applied-research/AnyJev/blob/35311c58955716cb8955ce1368a665988bc63735/tests/test_readme_numbers.py#L11)).

**Paper.** "AnyJev Technical Report", [arXiv:2610.00831](https://arxiv.org/abs/2610.00831), submitted 2026-09-30, cs.LG, linked from [README.md#L9](https://github.com/nokia-applied-research/AnyJev/blob/35311c58955716cb8955ce1368a665988bc63735/README.md#L9). I read only the abstract page, not the PDF.

## 2. How it works

The backend contract is a single method: `next_token_logprobs(prompts, token_ids)` returns, for each prompt, the log-probability of each requested token id, taken from the full-vocabulary log-softmax at the last position. A backend that cannot do this "is not a supported backend". `score_shared` is optional and reuses a prefix KV cache ([backends/base.py#L1-L31](https://github.com/nokia-applied-research/AnyJev/blob/35311c58955716cb8955ce1368a665988bc63735/anyjev/backends/base.py#L1-L31)).

### Data flow of one `Decider.decide` call

1. **Render the state** to text ([state.py#L8-L20](https://github.com/nokia-applied-research/AnyJev/blob/35311c58955716cb8955ce1368a665988bc63735/anyjev/state.py#L8-L20)).
2. **Choose the labels.** Letters for `choice`, `Yes`/`No` for `noul`, digits for `score` (falling back to letters). Each label must be exactly one token, and two labels may not share a token id. Anything else raises instead of "silently reading the wrong logit" ([readout.py#L24-L85](https://github.com/nokia-applied-research/AnyJev/blob/35311c58955716cb8955ce1368a665988bc63735/anyjev/readout.py#L24-L85)).
3. **Build one prompt per permutation.** The prompt is `State: … Question: … Options: A. … Answer with the letter only.` under a fixed system prompt ([readout.py#L14-L17](https://github.com/nokia-applied-research/AnyJev/blob/35311c58955716cb8955ce1368a665988bc63735/anyjev/readout.py#L14-L17), [#L98-L127](https://github.com/nokia-applied-research/AnyJev/blob/35311c58955716cb8955ce1368a665988bc63735/anyjev/readout.py#L98-L127)). It is rendered through the tokenizer's chat template with `enable_thinking=False` ([#L130-L139](https://github.com/nokia-applied-research/AnyJev/blob/35311c58955716cb8955ce1368a665988bc63735/anyjev/readout.py#L130-L139)). `raw` uses one ordering. `L0` uses the K cyclic shifts for `choice`, or both phrasings ("Yes or No" and "No or Yes") for `noul` ([decider.py#L436-L453](https://github.com/nokia-applied-research/AnyJev/blob/35311c58955716cb8955ce1368a665988bc63735/anyjev/decider.py#L436-L453)).
4. **Score the prompts.** The backend returns label log-probabilities, which are softmaxed over the labels only. Permutations of the same state share a prefix (the state comes before the options), so they can be scored against a single KV cache ([decider.py#L196-L229](https://github.com/nokia-applied-research/AnyJev/blob/35311c58955716cb8955ce1368a665988bc63735/anyjev/decider.py#L196-L229)).
5. **Correct for the label prior** (L0 only): divide by an estimated prior and renormalize ([calibrate/contextual.py#L1-L47](https://github.com/nokia-applied-research/AnyJev/blob/35311c58955716cb8955ce1368a665988bc63735/anyjev/calibrate/contextual.py#L1-L47)). The default `batch` prior is the running mean prediction for that question across all states the `Decider` has seen, raised to the power 0.75, and it applies only after 8 states ([decider.py#L38](https://github.com/nokia-applied-research/AnyJev/blob/35311c58955716cb8955ce1368a665988bc63735/anyjev/decider.py#L38), [#L181-L186](https://github.com/nokia-applied-research/AnyJev/blob/35311c58955716cb8955ce1368a665988bc63735/anyjev/decider.py#L181-L186), [#L544-L552](https://github.com/nokia-applied-research/AnyJev/blob/35311c58955716cb8955ce1368a665988bc63735/anyjev/decider.py#L544-L552)). The `content_free` option instead uses the answer to the probe inputs "N/A", "" and "[MASK]".
6. **Combine across permutations.** Average the log-probabilities and renormalize (`logmean`). If the position bias is additive in logit space, this removes it exactly ([calibrate/permute.py#L1-L14](https://github.com/nokia-applied-research/AnyJev/blob/35311c58955716cb8955ce1368a665988bc63735/anyjev/calibrate/permute.py#L1-L14), [#L48-L66](https://github.com/nokia-applied-research/AnyJev/blob/35311c58955716cb8955ce1368a665988bc63735/anyjev/calibrate/permute.py#L48-L66)).
7. **Return a `Decision`.** It carries `level` plus diagnostics such as `answer_mass` (the total probability the model put on the label tokens), `order_flip_raw`/`order_flip_l0` and `prior_method` ([decider.py#L554-L579](https://github.com/nokia-applied-research/AnyJev/blob/35311c58955716cb8955ce1368a665988bc63735/anyjev/decider.py#L554-L579); [docs/levels.md#L27-L30](https://github.com/nokia-applied-research/AnyJev/blob/35311c58955716cb8955ce1368a665988bc63735/docs/levels.md#L27-L30)).

### Key techniques

- **Published methods it implements:** contextual calibration (Zhao et al., ICML 2021), batch calibration (Zhou et al., ICLR 2024) and permutation debiasing (Zheng et al., ICLR 2024) ([CREDITS.md#L34-L36](https://github.com/nokia-applied-research/AnyJev/blob/35311c58955716cb8955ce1368a665988bc63735/CREDITS.md#L34-L36)).
- **Rotation budget.** This is opt-in. Rotations are read in a spread order (0, K/2, K/4, …), and reading stops once the log-odds gap between the top two options clears a threshold ([calibrate/permute.py#L30-L45](https://github.com/nokia-applied-research/AnyJev/blob/35311c58955716cb8955ce1368a665988bc63735/anyjev/calibrate/permute.py#L30-L45)). `calibrate_adaptive` sets that threshold from **unlabelled** states. It picks the cheapest threshold for which a Clopper-Pearson upper bound on disagreement with the library's own full-K answer stays under a target, so no labels are needed because the reference is the expensive answer, not ground truth ([calibrate/stopping.py#L1-L31](https://github.com/nokia-applied-research/AnyJev/blob/35311c58955716cb8955ce1368a665988bc63735/anyjev/calibrate/stopping.py#L1-L31), [#L106-L135](https://github.com/nokia-applied-research/AnyJev/blob/35311c58955716cb8955ce1368a665988bc63735/anyjev/calibrate/stopping.py#L106-L135); [decider.py#L261-L294](https://github.com/nokia-applied-research/AnyJev/blob/35311c58955716cb8955ce1368a665988bc63735/anyjev/decider.py#L261-L294)). Reported result: about 7.2 of 18 rotations, 2.2× throughput on vLLM and 2.3–2.7× on transformers, with accuracy unchanged ([docs/rotation_budget.md#L89-L105](https://github.com/nokia-applied-research/AnyJev/blob/35311c58955716cb8955ce1368a665988bc63735/docs/rotation_budget.md#L89-L105)). `canonical_order=True` sorts the options by their text before rotating, so the prompts depend only on which options there are, not the order they were passed in ([decider.py#L84-L93](https://github.com/nokia-applied-research/AnyJev/blob/35311c58955716cb8955ce1368a665988bc63735/anyjev/decider.py#L84-L93)).
- **Tacit.** The authors' checkpoints Tacit-1.7B to 9B, fine-tuned from Qwen3/Qwen3.5 ([README.md#L177-L189](https://github.com/nokia-applied-research/AnyJev/blob/35311c58955716cb8955ce1368a665988bc63735/README.md#L177-L189)). The README says they were "trained by self-distillation": the model learns to give, in one forward pass, the answer it reaches when it reasons ([README.md#L151-L154](https://github.com/nokia-applied-research/AnyJev/blob/35311c58955716cb8955ce1368a665988bc63735/README.md#L151-L154)). The repo contains no training code, so that claim is **unverified** from source. With `adaptive=True`, a decision whose top-two margin is below `tau` is re-asked with thinking on, and the final label distribution is read after `</think>`. Escalations are capped at `max_cot_share` of the last `cot_window` decisions, and the cap is shared across threads under a lock ([tacit.py#L358-L420](https://github.com/nokia-applied-research/AnyJev/blob/35311c58955716cb8955ce1368a665988bc63735/anyjev/tacit.py#L358-L420)).

### External dependencies

The core needs only `numpy` ([pyproject.toml#L30](https://github.com/nokia-applied-research/AnyJev/blob/35311c58955716cb8955ce1368a665988bc63735/pyproject.toml#L30)). The extras are `hf` (torch, transformers), `vllm`, `client` (transformers, for its tokenizer only), `llamacpp` and `eval` ([pyproject.toml#L32-L42](https://github.com/nokia-applied-research/AnyJev/blob/35311c58955716cb8955ce1368a665988bc63735/pyproject.toml#L32-L42)). There is no OpenAI, Anthropic, Ollama or other hosted-API backend. Ollama and MLX are listed as help wanted ([ROADMAP.md#L81-L84](https://github.com/nokia-applied-research/AnyJev/blob/35311c58955716cb8955ce1368a665988bc63735/ROADMAP.md#L81-L84)).

- `VLLMBackend` calls `/v1/completions` with `max_tokens=1`, `allowed_token_ids` set to the labels, and `logprobs=K`. The vLLM server must run with `--logprobs-mode processed_logprobs`, and a missing label raises `LabelTokenError` ([backends/vllm.py#L1-L29](https://github.com/nokia-applied-research/AnyJev/blob/35311c58955716cb8955ce1368a665988bc63735/anyjev/backends/vllm.py#L1-L29), [#L58-L83](https://github.com/nokia-applied-research/AnyJev/blob/35311c58955716cb8955ce1368a665988bc63735/anyjev/backends/vllm.py#L58-L83)). The client loads the model's Hugging Face tokenizer and renders the chat template itself.
- `SGLangBackend` uses the native `/generate` endpoint ([backends/sglang.py#L1-L17](https://github.com/nokia-applied-research/AnyJev/blob/35311c58955716cb8955ce1368a665988bc63735/anyjev/backends/sglang.py#L1-L17)). `LlamaCppBackend` loads GGUF files in-process and checks that tokenization matches the Hugging Face tokenizer ([backends/llamacpp.py#L1-L22](https://github.com/nokia-applied-research/AnyJev/blob/35311c58955716cb8955ce1368a665988bc63735/anyjev/backends/llamacpp.py#L1-L22)).

## 3. Usage

Install with `pip install anyjev`, adding `"anyjev[hf]"`, `"anyjev[vllm]"`, `"anyjev[client]"` or `"anyjev[llamacpp]"` for a backend ([pyproject.toml#L32-L42](https://github.com/nokia-applied-research/AnyJev/blob/35311c58955716cb8955ce1368a665988bc63735/pyproject.toml#L32-L42)). Python 3.10 or later ([#L12](https://github.com/nokia-applied-research/AnyJev/blob/35311c58955716cb8955ce1368a665988bc63735/pyproject.toml#L12)).

Minimal training-free example ([README.md#L118-L127](https://github.com/nokia-applied-research/AnyJev/blob/35311c58955716cb8955ce1368a665988bc63735/README.md#L118-L127)):

```python
from anyjev import Decider, Question
from anyjev.backends.vllm import VLLMBackend   # or HFBackend("Qwen/Qwen3-8B")

d = Decider(VLLMBackend("http://localhost:8000", "Qwen/Qwen3-8B"))   # level="L0" by default
route = Question.choice("Which team should handle this?", ["billing", "technical", "sales", "other"], name="route")
r = d.decide("My card was charged twice for one order.", [route])["route"]
r.distribution, r.level            # {option: probability}, "L0"
```

Tacit example: `Tacit.from_pretrained("morriszjm/Tacit-9B", engine="transformers"|"vllm"|"server", adaptive=True)`, then `tacit.decide(state=..., question=..., options=[...], kind="choice"|"yes_no"|"score")`. It returns a dict with `answer`, `probs`, `margin` and `route` ([README.md#L56-L79](https://github.com/nokia-applied-research/AnyJev/blob/35311c58955716cb8955ce1368a665988bc63735/README.md#L56-L79); [docs/levels.md#L35-L57](https://github.com/nokia-applied-research/AnyJev/blob/35311c58955716cb8955ce1368a665988bc63735/docs/levels.md#L35-L57)).

CLI and HTTP surface:

- `python -m anyjev.serve --model … --upstream http://127.0.0.1:8000 --adaptive --port 8100` serves `POST /v1/decide`, `GET /v1/stats` and `GET /health`. It binds to 127.0.0.1 by default and has no authentication ([serve.py#L24-L82](https://github.com/nokia-applied-research/AnyJev/blob/35311c58955716cb8955ce1368a665988bc63735/anyjev/serve.py#L24-L82)).
- `python -m anyjev.truncate MODEL BLOCKS OUT` ([truncate.py#L95-L103](https://github.com/nokia-applied-research/AnyJev/blob/35311c58955716cb8955ce1368a665988bc63735/anyjev/truncate.py#L95-L103)).

Main `Decider` settings ([decider.py#L40-L48](https://github.com/nokia-applied-research/AnyJev/blob/35311c58955716cb8955ce1368a665988bc63735/anyjev/decider.py#L40-L48)):

- `level`: `raw` or `L0`.
- `prior`: `batch`, `content_free` or `none`.
- `prior_strength`.
- `max_permutations`.
- `shared_prefix`.
- `adaptive_shifts`, `canonical_order`, `adaptive_target`, `adaptive_wave`.
- `require="L0"` on `decide` raises `LevelError` when a decision comes back below that level ([decider.py#L153-L161](https://github.com/nokia-applied-research/AnyJev/blob/35311c58955716cb8955ce1368a665988bc63735/anyjev/decider.py#L153-L161)).

## 4. Limitations, open issues and surprises

**Documented limitations** ([docs/limitations.md#L6-L25](https://github.com/nokia-applied-research/AnyJev/blob/35311c58955716cb8955ce1368a665988bc63735/docs/limitations.md#L6-L25)):

- Accuracy is still bounded by the underlying model.
- Tacit's one-forward path does not average over option orders.
- An escalated decision takes seconds, not milliseconds.
- `choice` allows at most 26 options.
- The batch prior hurts accuracy when one label dominates a batch.
- Coverage at 5% risk is a high-variance estimate at n = 300.
- Every published result scores decisions one at a time, never inside an agent loop.

**Open work.**

- Issues: an Ollama backend design ([#18](https://github.com/nokia-applied-research/AnyJev/issues/18)). Ollama's `top_logprobs` is capped at 20 and it has no `allowed_token_ids`, so the backend has to fail closed. Also open: a proposal to gate graph traversal with AnyJev decisions ([#3](https://github.com/nokia-applied-research/AnyJev/issues/3)) and an external experiment on value extraction ([#16](https://github.com/nokia-applied-research/AnyJev/issues/16)).
- PRs: an MLX backend ([#15](https://github.com/nokia-applied-research/AnyJev/pull/15)), histogram binning ([#17](https://github.com/nokia-applied-research/AnyJev/pull/17)) and a Strata backend ([#20](https://github.com/nokia-applied-research/AnyJev/pull/20)).
- Roadmap items still to do: span readout for more than 26 options, conformal abstention, an agentic evaluation, and multimodal states ([ROADMAP.md#L56-L92](https://github.com/nokia-applied-research/AnyJev/blob/35311c58955716cb8955ce1368a665988bc63735/ROADMAP.md#L56-L92)). For images, the maintainers currently suggest a manual workaround ([#19](https://github.com/nokia-applied-research/AnyJev/issues/19)).

**Surprises and README/code disagreements**

- **`L0` does not always mean the prior was applied.** The batch prior needs 8 states for the same question key. Before that, `prior_used` is `None`, yet the decision is still labelled `"L0"` ([decider.py#L183-L186](https://github.com/nokia-applied-research/AnyJev/blob/35311c58955716cb8955ce1368a665988bc63735/anyjev/decider.py#L183-L186), [#L561-L568](https://github.com/nokia-applied-research/AnyJev/blob/35311c58955716cb8955ce1368a665988bc63735/anyjev/decider.py#L561-L568)). Only `diagnostics["prior_method"] == "none"` reveals it. [docs/levels.md#L17-L18](https://github.com/nokia-applied-research/AnyJev/blob/35311c58955716cb8955ce1368a665988bc63735/docs/levels.md#L17-L18) mentions "from 8 states on", but the `level` contract does not separate the two cases. A question's key hashes its text ([question.py#L70-L76](https://github.com/nokia-applied-research/AnyJev/blob/35311c58955716cb8955ce1368a665988bc63735/anyjev/question.py#L70-L76)), so a question that embeds the user's wording never collects a prior.
- **The batch prior accumulates forever** for each `Decider` and question, and nothing resets it ([decider.py#L546-L547](https://github.com/nokia-applied-research/AnyJev/blob/35311c58955716cb8955ce1368a665988bc63735/anyjev/decider.py#L546-L547)). The PR that would have added `reset_prior()` was closed by its author, who said an AI agent had opened it ([#14](https://github.com/nokia-applied-research/AnyJev/pull/14)). In a long-running service, the prior drifts with the traffic mix.
- **Failure handling differs between paths.** The `Decider` path on vLLM raises when a label is missing ([CHANGELOG.md#L27-L33](https://github.com/nokia-applied-research/AnyJev/blob/35311c58955716cb8955ce1368a665988bc63735/CHANGELOG.md#L27-L33)). Tacit's vLLM engines read only the top-20 log-probabilities and treat a missing label as probability 0. If every label is missing, they silently return a uniform distribution ([tacit.py#L59-L65](https://github.com/nokia-applied-research/AnyJev/blob/35311c58955716cb8955ce1368a665988bc63735/anyjev/tacit.py#L59-L65), [#L178-L186](https://github.com/nokia-applied-research/AnyJev/blob/35311c58955716cb8955ce1368a665988bc63735/anyjev/tacit.py#L178-L186)). The limitations doc mentions the first behaviour but not the uniform fallback.
- **The headline table predates the current defaults.** It was produced with anyjev 0.0.2 ([the JSON's `env.anyjev`](https://github.com/nokia-applied-research/AnyJev/blob/35311c58955716cb8955ce1368a665988bc63735/bench/results_v01/2026-09-22/Qwen__Qwen3-8B.json)), before the default prior strength became 0.75 in 0.1 ([ROADMAP.md#L24-L25](https://github.com/nokia-applied-research/AnyJev/blob/35311c58955716cb8955ce1368a665988bc63735/ROADMAP.md#L24-L25)). The same JSON also shows where the gains come from. Permutation averaging alone (`L0-perm`) brings coverage only to 33.7%. Batch calibration alone (`L0-bc`, one prompt) reaches 48.0% coverage but leaves the flip rate at 0.223.
- **"Two rotations" on the Decision Index board** means `max_permutations=2` ([examples/decision_index/anyjev_engine.py#L78-L88](https://github.com/nokia-applied-research/AnyJev/blob/35311c58955716cb8955ce1368a665988bc63735/examples/decision_index/anyjev_engine.py#L78-L88)). That gives the first two consecutive shifts ([permute.py#L24-L27](https://github.com/nokia-applied-research/AnyJev/blob/35311c58955716cb8955ce1368a665988bc63735/anyjev/calibrate/permute.py#L24-L27)), not a full cancellation of position bias. The same example goes beyond the library's 26-option cap with two-level letter+digit labels (up to 260 options) ([#L196-L222](https://github.com/nokia-applied-research/AnyJev/blob/35311c58955716cb8955ce1368a665988bc63735/examples/decision_index/anyjev_engine.py#L196-L222)). The leaderboard placements themselves are **unverified**: I did not open the board.
- **The API breaks quickly.** Version 0.3.0 removed the label-trained levels L1 and L2, routing and `observe` only eight days after 0.2.0 ([CHANGELOG.md#L65-L71](https://github.com/nokia-applied-research/AnyJev/blob/35311c58955716cb8955ce1368a665988bc63735/CHANGELOG.md#L65-L71)). Issue #3 refers to directories (`bench/tasks/`, `bench/games/`, `demo/`) that no longer exist.
- **Naming is inconsistent.** The README calls the yes/no kind `"yes_no"` ([README.md#L66](https://github.com/nokia-applied-research/AnyJev/blob/35311c58955716cb8955ce1368a665988bc63735/README.md#L66)), while the core type is `"noul"` ([question.py#L20](https://github.com/nokia-applied-research/AnyJev/blob/35311c58955716cb8955ce1368a665988bc63735/anyjev/question.py#L20)). Tacit accepts both ([tacit.py#L56](https://github.com/nokia-applied-research/AnyJev/blob/35311c58955716cb8955ce1368a665988bc63735/anyjev/tacit.py#L56)). The `Decider` docstring cites `docs/when_l0_helps.md` ([decider.py#L49-L52](https://github.com/nokia-applied-research/AnyJev/blob/35311c58955716cb8955ce1368a665988bc63735/anyjev/decider.py#L49-L52)), which is not in the tree. It only exists at tag v0.2.0.
- **A benchmark dataset has no stated license.** bev-decision is marked `license: unknown` ([THIRD_PARTY.md#L49](https://github.com/nokia-applied-research/AnyJev/blob/35311c58955716cb8955ce1368a665988bc63735/THIRD_PARTY.md#L49)).

## 5. Relevance to docs-analyzer

**Bottom line: low to moderate.** docs-analyzer's core is Docling conversion, chunking, Regions, retrieval, and open-ended answers with `[n]` citations ([CONTEXT.md](../../CONTEXT.md); [graph.py#L174-L187](../../backend/app/graph.py#L174-L187)). None of that is a typed decision, and AnyJev has nothing about documents, layout, bounding boxes or retrieval. AnyJev helps only with the few places where the backend asks an LLM a closed question, and it depends on token log-probabilities, which the deployed vLLM server can provide.

**Precondition: the provider.** In the deployed setup, Ollama serves only the embedding model. The chat LLM is Qwen3.5-4B-AWQ served by vLLM ([laporan-tugas-besar.md#L46](../laporan-tugas-besar.md#L46)), reached through LangChain `ChatOpenAI` as an OpenAI-compatible provider ([models.py#L34-L54](../../backend/app/models.py#L34-L54), [backend/.env.example#L1-L9](../../backend/.env.example#L1-L9)). AnyJev never touches embeddings, so this setup already meets its main requirement: `VLLMBackend` can call the same vLLM server's `/v1/completions`. Two things still have to hold:

- the server runs with `--logprobs-mode processed_logprobs`;
- the model's Hugging Face tokenizer can be loaded by name (the `tokenizer_name` argument handles a served alias).

The code default is still `llm_provider = "ollama"` ([config.py#L12-L15](../../backend/app/config.py#L12-L15)), and the Settings screen can point the chat model at any OpenAI-compatible server, including hosted ones without log-probabilities. So the feature belongs behind a flag and should fail soft (skip the check) when the server returns no log-probabilities.

The core package only needs numpy, and `transformers` is already a dependency here ([backend/pyproject.toml](../../backend/pyproject.toml)). Python 3.12 is inside AnyJev's tested range. Given the pre-alpha churn, pin `anyjev==0.3.0`.

**What could apply, and where**

| Idea | Where it fits | How | Caveats |
|---|---|---|---|
| **Answerability gate.** A probability that the fused context actually contains the answer | A new node between `fuse` and `generate` in [graph.py#L127-L171](../../backend/app/graph.py#L127-L171). It replaces relying only on the prompt's "If the context does not contain the answer, say so" ([prompts/chat.py#L3-L7](../../backend/app/prompts/chat.py#L3-L7)) | `Question.noul("Does the context contain the answer to the question?")` with a fixed text, and the question plus context blocks passed as the state. L0 reads both phrasings, and vLLM prefix caching reuses the shared context ([vllm.py#L12-L15](https://github.com/nokia-applied-research/AnyJev/blob/35311c58955716cb8955ce1368a665988bc63735/anyjev/backends/vllm.py#L12-L15)) | Labels are skewed (most questions are answerable), so use `prior="content_free"` or `"none"` ([limitations.md#L18-L19](https://github.com/nokia-applied-research/AnyJev/blob/35311c58955716cb8955ce1368a665988bc63735/docs/limitations.md#L18-L19)). Choosing the threshold needs a few labelled Turns. Cost is two prefills of up to `context_token_budget` (8000) tokens per Turn |
| **Citation support check.** Drop or flag an `[n]` whose block does not support the sentence that cites it | After `generate` in [graph.py#L158-L171](../../backend/app/graph.py#L158-L171), before `to_citations` ([#L143-L155](../../backend/app/graph.py#L143-L155)) | One `noul` per (sentence, cited block) pair, run in a batch with `decide_batch` | This strengthens the project's main promise, that every Highlighted Region really supports the answer. Cost is one or two prefills per citation. Its value on this model is **unmeasured** |
| **Section choice as a typed choice** | [retrieval/tree_search.py#L37-L56](../../backend/app/retrieval/tree_search.py#L37-L56), which today generates a list of ids through `with_structured_output` | Present the sections as `choice` options and take the top-k by probability. This gives a confidence score and removes parse failures | Capped at 26 options, while a long document's outline is often bigger. L0 reads K rotations of the whole outline, and since the options are the bulk of that prompt, the shared-prefix cache saves little. So use `level="raw"` or `max_permutations=2`. Position bias (0.230 flip rate in AnyJev's raw measurement) may affect the current generated choice as well; that is **unverified here** |
| **Gating graph traversal** | [retrieval/kg.py#L46-L64](../../backend/app/retrieval/kg.py#L46-L64), which always expands 1 to 2 hops | `noul` "relevant?" and "expand?" checks per hop, as proposed in issue #3 | A proposal only. Upstream has no code or results |
| **Ideas to copy without the dependency** | Any LLM call | Refuse labels that are not a single token or that collide ([readout.py#L63-L85](https://github.com/nokia-applied-research/AnyJev/blob/35311c58955716cb8955ce1368a665988bc63735/anyjev/readout.py#L63-L85)). Log an `answer_mass`-style signal ("did the prompt land"). Pick a cheap path's threshold by its certified agreement with the expensive path on unlabelled data ([stopping.py#L106-L135](https://github.com/nokia-applied-research/AnyJev/blob/35311c58955716cb8955ce1368a665988bc63735/anyjev/calibrate/stopping.py#L106-L135)) | The last idea fits a question like "can long documents skip a retriever?", but only once such a cheap/expensive choice exists |

**What would not apply**

- **Answer generation, query rewriting (`contextualize`), section summaries and graph extraction.** These all produce free text or structured output ([graph.py#L70-L91](../../backend/app/graph.py#L70-L91), [ingest/kg.py#L32-L35](../../backend/app/ingest/kg.py#L32-L35), [ingest/tree.py](../../backend/app/ingest/tree.py)). AnyJev never generates text (except in Tacit's escalation path) ([AGENTS.md#L6](https://github.com/nokia-applied-research/AnyJev/blob/35311c58955716cb8955ce1368a665988bc63735/AGENTS.md#L6)).
- **Ingest, Docling, chunking, Regions, page rendering.** AnyJev has no overlap with any of these.
- **Tacit models and self-distillation.** They are decision models, not answer writers, and their training code is not published.
- **`detect_language`** ([ingest/pipeline.py#L28-L37](../../backend/app/ingest/pipeline.py#L28-L37)). It could be a `choice` over a fixed language list, but it is open-ended today, already fails soft, and runs once per Document. There is little to gain.
- **Embeddings (Ollama), and hosted OpenAI or OpenRouter chat models** if the chat model is ever switched away from vLLM, as explained under the precondition above.

If this is pursued, the cheapest test is a throwaway spike: run the answerability gate on 20–30 real Turns against the vLLM server and see whether p(Yes) separates the answerable Turns from the unanswerable ones.
